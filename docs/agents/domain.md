# Domain documentation

Before exploring an area of the project, read `GLOSSARY.md` at the repository
root and any relevant architecture decision records (ADRs) in `docs/adr/`.
If those files do not yet exist, continue with the work. The `domain-modeling`
skill records terms as they are defined and decisions as they are made.

Use glossary terms in issues, proposals, and tests. If the project uses a concept
that the glossary does not cover, flag the gap for `domain-modeling`.

If a proposal conflicts with a recorded decision, cite the relevant ADR and
explain why the decision is worth revisiting.
